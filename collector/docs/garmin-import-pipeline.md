# 주간 기록 통합 가져오기

오늘 화면과 Garmin 관리 화면의 주간 가져오기 버튼 한 번으로 다음 순서를 실행합니다.

1. 저장된 Garmin 인증 확인. 비밀번호·MFA 입력은 터미널에서 최초 연결/재연결할 때만 진행.
2. 서버 `TRAINI_TIMEZONE`의 대상 주간 러닝 조회 및 원본 FIT 저장/검증. 기본은 이번 주 월요일부터 오늘까지이며, 완료된 지난 월~일로 전환 가능.
3. **이번 조회에서 성공적으로 확인한 파일만** 공식 Garmin FIT SDK로 정규화.
4. 원본·정규화 해시와 재디코딩 결과를 확인하고 관리자 소유의 기존 `activities`에 RPC 업로드.
5. 실행 종료 시 DB에서 주간 요약을 다시 조회. 화면에서 선택한 이번 주/지난주는 유지.

기간은 Next 서버가 실행 요청을 처리할 때 고정하고 Python에도 날짜 인자로 전달합니다.
일요일 요청의 작업이 월요일에 시작되더라도 원래 범위를 유지합니다.
[주간 마감과 날짜 경계](../../docs/weekly-training-closeout.md)를 참고하세요. API의 날짜 조회를 통과해도 FIT 자체의 UTC 시작 시각을
훈련 시간대로 변환한 날짜가 대상 주간 밖이면 분석 실패로 남기고 업로드하지 않습니다.
관련 없는 과거 파일이나 이전 실행의 성공 manifest를 가져다 업로드하지 않습니다.
활동이 없는 주는 0개로 정상 종료하며, DB의 기존 기록을 삭제하지 않습니다.

## 실행과 데이터 경계

서버 검증 관리자 세션과 요청 Origin을 확인한 Next 서버만 고정 Python 모듈을 실행합니다.
사용자가 보낸 명령·경로·사용자 UUID는 사용하지 않습니다. 수집기 실행 경로는 절대 경로의
실행 가능 파일이어야 합니다. 서버 설정의 관리자 UUID와 인증된 관리자 UUID도 일치해야 합니다.
서버 키는 고정 Supabase 프로젝트를 사용하는 로컬 자식 프로세스에만 전달하며, 다른 앱 키는
상속하지 않습니다. 키·Garmin 토큰·원본 FIT·프로세스 PID·로컬 경로는 상태 API로 보내지 않습니다.

로컬 Mac Next 서버, 최초 Garmin 인증, `.env.local`의 수집기 및 기존 Supabase 설정이 필요합니다.
Vercel에서는 실행하지 않습니다. Python 실행 제한은 전체 5분이며 네트워크 요청에도 시간 제한과
재시도 상한이 있습니다. 브라우저를 닫아도 프로세스는 계속되고 다음 방문 시 상태를 확인합니다.

수집·분석·업로드 **전 구간에 하나의 `.sync.lock`**을 유지합니다. CLI와 다른 웹 요청의 동시
실행은 거절합니다. 잠금을 가진 웹 작업에서 내부 분석/업로드 함수를 호출하므로 잠금을 중첩해
획득하지 않습니다. 독립 CLI의 잠금 및 모든 파일을 처리하는 기존 동작은 유지합니다.

## 진행 상태와 재실행

`web-sync.json` version 2는 수집/분석/업로드별 개수, 현재 단계, 최초 실패 단계와 안전한 오류
코드만 기록합니다. 시작·단계 전환·활동별 처리·종료 때 원자적으로 저장합니다. 화면은 실행 중
주기적으로 조회하며, 프로세스 종료나 제한 시간 초과로 남은 실행을 중단 상태로 표시합니다.
version 1의 과거 다운로드 결과는 업로드 완료로 표시하지 않습니다.

- 수집 실패: 성공한 파일은 계속 분석·업로드. 실패한 활동의 과거 JSON은 재사용하지 않음.
- 분석 실패: 원본과 과거 파생 파일은 보존하되 현재 manifest에서 실패 처리하여 업로드 제외.
- 업로드 실패: 다른 활동 저장은 계속. 전체 DB 작업을 하나의 트랜잭션으로 되돌리지 않음.
- 인증·조회·설정 등 실행 자체 실패: 이전 manifest로 다음 단계를 시작하지 않음.
- 저장 도중 응답 손실·중단: DB에 반영됐을 수 있어 완료 화면에서는 요약을 재조회.

다시 누르면 전체 대상 주간을 확인합니다. 정상 원본과 동일한 정규화 파일은 재사용하고,
DB는 매번 멱등 RPC로 비교하여 `inserted` / `updated` / `unchanged`를 확인합니다.
화면의 **저장·갱신**은 inserted+updated, **기존 기록**은 unchanged입니다. 실패 개수는
수집+분석+업로드 실패 합계이며 분석 실패로 인한 upload excluded는 다시 더하지 않습니다.
원격 저장 후 로컬 체크포인트 저장에 실패해도 재실행하면 같은 활동이 추가 생성되지 않습니다.

`parse-state.json`과 `upload-state.json`은 이번 실행의 범위로 갱신됩니다. 과거 파일 전체를
분석하려면 `traini-parse`를 실행한 뒤 필요 시 `npm run garmin:upload`를 사용합니다.
매주 버튼을 사용하는 흐름에서는 이 두 명령을 별도로 실행할 필요가 없습니다.

## 검증

```sh
collector/.venv/bin/python -m unittest discover -s collector/tests -q
npm run test:garmin
npm run test:admin
npm run test:summary
npm run lint
npm run build
```

합성 FIT와 메모리 저장소로 실제 디코더를 통과하는 전체 흐름, 반복 실행, 일부 실패,
정상 파일만 진행, 주간 불일치, 빈 주간, 이전 manifest 재사용 방지, 잠금, 업로드 중단과
복구를 검증합니다. 실제 계정/서버 키는 자동 테스트에 사용하지 않습니다.

## 훈련 완료 연결

가져오기 후 최근 8주와 이번 주의 저장된 훈련계획을 Garmin 활동과 연결합니다. 연결 실패는
가져오기 결과와 구분해 안내하며 재확인할 수 있습니다. 여러 활동·불완전한 세션은 자동 완료하지
않습니다. [연결 기준과 검증](../../docs/garmin-workout-matching.md)을 참고하세요.
