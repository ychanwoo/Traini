# 검증·출시 확인

문서가 정리됐다는 사실과 실제 서비스가 현재 환경에서 검증됐다는 사실은 다릅니다.
이 문서는 **이미 있는 검사**, **개인이 실행해서 확인할 항목**, **필요할 때만 확장할 범위**를 구분합니다.
개인 훈련 데이터와 실제 모델 응답은 공개 검증 자료로 사용하지 않습니다.

## AI 호출 없는 검증

| 구분 | 명령 | 확인 범위·경계 |
| --- | --- | --- |
| 웹 단위·서비스 로직 | `npm test` | 합성 데이터·대역을 사용하는 오프라인 Node 검사 |
| 수집기·FIT | `collector/.venv/bin/python -m unittest discover -s collector/tests -q` | 실제 FIT 인코더·디코더와 합성 파일. Garmin 계정 접속 없음 |
| 정적 검사 | `npm run lint`, `npm run typecheck`, `npm run build` | 코드·타입·페이지 빌드. 실계정 사용 성공을 보증하지 않음 |
| 브라우저 | `npm run test:e2e` | 실제 컴포넌트·스타일과 격리된 합성 API. 실제 Google 로그인·Proxy·RLS는 별도 |
| 실서버 인증 | `npm run test:admin:integration` | 로컬 3017 서버와 설정된 DB 필요. 익명·비관리자·관리자·CSRF 검사 |
| DB 통합 | `npm run test:closeout:integration`, `npm run test:review:integration`, `npm run test:prescription:integration`, `npm run test:feedback:integration` | 임시 계정과 실제 DB 트랜잭션. 생성 응답은 고정 대역이며 실제 추론 없음 |
| SQL 제약 | `npm run test:db:closeout` 등 `test:db:*` | 연결된 프로젝트의 트랜잭션·권한 검사. DB 접근·쓰기 후 rollback이 있으므로 오프라인 검사가 아님 |
| 개인 저장 계획 감사 | `npm run test:plan:personal` | 실제 관리자 계획·조건을 읽는 인수 검사. 새 AI 계획 생성 없음 |

통합 검사는 `.env.local`과 지정된 개발 프로젝트를 사용하며 임시 계정 생성·정리 등 실제 DB 쓰기가 있습니다.
AI를 쓰지 않는다는 말이 외부 접속이나 모든 쓰기가 없다는 뜻은 아닙니다.
각 검사의 전제와 보존 경계는 [운영·복구](service-reliability.md),
[개인 인수 확인](personal-training-plan-validation.md), [브라우저 검사](weekly-coaching-e2e.md)에 있습니다.

`test:subscription:live`는 실제 추론이 가능한 별도 opt-in 검사입니다. 기본 검증에 포함하지 않습니다.
`test:weather:provider`도 실제 OpenWeather 요청을 보내므로 오프라인 검사와 구분합니다.
이 문서 작업에서는 두 명령을 실행하지 않습니다.

## 개인 사용을 마무리하기 위해 확인할 항목

| 항목 | 완료 판단 기준 |
| --- | --- |
| GitHub CI | push 후 해당 PR에서 웹·Python 두 버전·브라우저·집계 검사가 통과하고 결과 링크를 확인 |
| main 보호 | `Required checks`가 실제 ruleset의 필수 검사이고 PR·Active 조건이 적용됐는지 사용자가 확인 |
| 실제 계정 연결 | 관리자 Google 로그인·로그아웃·원래 페이지 복귀, Garmin 재인증, 별도 ChatGPT 연결 상태를 직접 확인 |
| 실제 주간 흐름 | 일요일 마감 또는 월요일 지난주 처리 → 리뷰 → 원하는 주 계획을 필요할 때 명시적으로 실행 |
| 늦은 변경 | 가져오기·피드백 변경 후 재확인·오래된 계획 안내를 보고, 완료·건너뜀 기록이 유지되는지 확인 |
| 실제 출력 품질 | 새 계획을 만들 필요가 생겼을 때만 한 번 생성하고 숫자뿐 아니라 요약·날짜·근거 설명도 검토 |
| 사용량 설정 | Traini의 rolling 한도와 별도로 제공자 계정의 크레딧 사용·자동 충전 설정을 확인 |
| 데이터 복구 | 원본 FIT·비공개 인증 자료·DB 백업을 서로 구분하고, 비밀이 없는 테스트 환경에서 복구 절차를 확인 |

이 표는 자동으로 완료 표시되는 상태판이 아닙니다. 저장소의 코드만 읽고 원격 CI·계정 설정·백업 복구가
이미 통과했다고 주장하지 않습니다. 일요일·월요일 로직은 자동 테스트로 검증하지만 실제 운영 확인을 대신하지 않습니다.

## 필요할 때 별도로 확장할 범위

- **휴대폰 원격 접속:** 주소·TLS·OAuth redirect·쿠키·로컬 연결 제한까지 포함한 구성과 검증.
- **상시 운영:** Mac 잠자기·재시작·서버 중단 시 복구, 수집기·인증 자료를 유지할 실행 환경.
- **다른 사람의 설치:** 개인 Supabase 프로젝트 제한 제거와 신규 사용자·프로필 초기 설정 절차.
- **새 데이터:** 수면·HRV·회복 지표는 별도 수집·출처·권한·누락 처리 설계가 필요함.
- **자동화:** 예약 수집·리뷰·계획 갱신은 현재 없음. 추가 시 명시적 동의·한도·실패 보존을 함께 설계.

모든 확장이 개인 사용의 필수 조건은 아닙니다. 현재 로컬 사용 범위를 유지한다면 운영 확인을 먼저 마무리하고,
실제 사용에서 필요한 문제를 다음 이슈로 나누는 편이 좋습니다.

## 포트폴리오 공개 기준

기능 설명은 실제 페이지·API·저장 경로로 확인할 수 있어야 합니다.
원본 FIT와 정규화 파일, 실계정 화면, DB 행·OAuth 링크·인증·환경변수 파일은 자료로 첨부하지 않습니다.
`.gitignore`에 있더라도 과거 Git 이력이나 수동 첨부까지 자동으로 보호되지는 않습니다.

화면 자료가 필요하면 다음 합성 데이터 서버를 사용합니다.

```sh
npm run test:e2e:serve
```

[테스트 일정 화면](http://127.0.0.1:3027/schedule) 또는
[테스트 오늘 화면](http://127.0.0.1:3027/today)을 열고,
현재 상태에 맞는 test scenario를 선택합니다. 이 화면은 개인 계정 데이터를 읽지 않습니다.
실제 UI 컴포넌트와 CSS를 사용하지만 예시 수치·모델명은 테스트 값입니다.
화면을 공개할 때 **합성 데이터로 촬영한 검증 화면**이라고 명시하고 실계정의 실제 AI 결과로 설명하지 않습니다.
테스트 컨트롤·모델명을 숨겨 실제 운영 결과처럼 꾸미지 않습니다.

공개 전에 이름·이메일·사진·계정/활동 ID·대회명·목표 기록·증상·위치·토큰이 없는지 파일 자체를 확인합니다.
기존 자료에 비밀이 있었다면 문서에서 지우는 것과 별개로 해당 비밀의 교체와 Git 이력 검토가 필요합니다.

## 이번 문서 정리의 검증 범위

README·기능 문서를 현재 페이지·API·생성 입력·수집기·환경 설정·검사 명령과 대조합니다.
저장소 내부 링크·앵커·명령 이름과 개인정보 예시를 검사합니다.
문서 수정으로 실제 서비스·DB·인증 설정·UI는 변경하지 않으며, 실계정 데이터와 외부 추론을 사용하지 않습니다.
검증 결과는 이번 작업 보고와 실제 CI 결과를 기준으로 확인합니다.
