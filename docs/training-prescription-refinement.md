# 여러 대회 목표와 훈련 처방

## 사용 흐름

`마이 → 내 목표 및 대회`에서 대회를 추가하고 각 날짜·거리·목표 기록을 입력한다.
최대 8개를 보관하며 주목표는 하나다. 예를 들어 1월 하프를 준비 대회, 3월 풀을
주목표로 지정하면 두 대회의 목표 기록, 대회 전 조정, 대회 후 회복을 함께 전달한다.
목표 기록은 현재 수행 능력의 증거가 아니다. 가까운 대회가 충돌하면 경고를 표시하며
두 기록을 동시에 달성한다고 보장하지 않는다. 지난 대회는 회복 구간 판단을 위해 남길 수 있다.

컨디션은 직접 입력한 날짜와 함께 저장한다. 피로 입력은 입력일을 포함한 3일 동안
해당 날짜의 거리·페이스·훈련 종류를 제한한다. 통증·몸 상태 이상은 사용자가
수정/해제하기 전까지 새 러닝 배치를 보류한다. 좋은 컨디션만으로 부하를 늘리지 않는다.
미입력·오래된 정상 보고를 현재 상태로 추정하지 않는다. 같은 상태를 오늘 다시 보고하려면
`같은 컨디션으로 오늘 다시 기록`을 누르고 저장한다.

목표·오늘·일정의 `훈련 처방 기준`은 기록과 규칙으로 계산한 조회 결과다.
조회·목표 저장에는 OpenAI를 호출하지 않는다. 이미 저장된 계획은 자동으로 변경하지 않고
기존 생성 버튼에서만 새 입력을 사용한다. 이 작업의 실제 모델 호출은 0회이며
생성→검증→DB 저장 테스트에서는 고정 응답을 주입한다.

## 근거와 제약

- 완료된 최근 8주, 지난주 계획과 Garmin 수행 연결, 이번 주 누적 활동을 함께 읽는다.
  수동 완료와 미확인 활동을 수행 실패로 간주하지 않는다. 기록 부족만으로 부하를 삭감하지 않는다.
- 훈련 종류/순서는 고정하지 않는다. 장거리 요일은 선호이며, 가능한 훈련일과
  대회 보호 구간·회복 간격 안에서 다른 날짜를 선택할 수 있다.
- 회복런은 별도 `recovery` 종류로 이지런보다 느린 페이스와 짧은 거리 상한을 적용한다.
  이지런·롱런은 측정된 일반 러닝/장거리 근거, 템포는 지속 active 구간을 사용한다.
  근거 없는 템포 숫자 페이스를 인터벌 평균으로 만들지 않는다.
- 워밍업·쿨다운과 더 빠른 active 랩이 모두 확인된 세션에서 400m/800m를 각각 분리한다.
  최근 반복 수, 작업 페이스, 회복 거리/페이스로 제한하고 속도·반복 수 동시 증가는 거부한다.
  근거 없는 인터벌은 숫자 작업 페이스 없이 200–1000m, 최대 8회,
  작업 거리의 0.5–1.5배 회복 범위만 허용한다. 모든 종류를 매주 강제하지 않는다.
- 두 개 이상 Garmin 확인 세션의 거리가 계획의 80% 미만이면 증가를 보류한다.
  이를 피로·실패 진단으로 해석하지 않는다. 대회 조정·회복 주에도 반복 수 증가를 보류한다.
- 대회 거리를 주간 예산에서 예약하고 대회가 고강도 한 슬롯을 사용하도록 한다.
  실제 대회 활동이 수집되면 중복 차감하지 않는다. 대회일은 일반 러닝 처방과 분리해
  캘린더에 표시한다. 원본 FIT와 기존 과거·완료 훈련은 보존한다.

수치 상한은 목표나 생리학적 예측이 아닌 애플리케이션 검증 규칙이다.
FIT의 lap intensity가 없거나 부정확하면 구간별 능력을 확정하지 않는다.
수면·HRV·부상·현재 컨디션을 러닝 거리만으로 추정하지 않는다.

## 저장·동시성

`20261016060000`은 `profiles.race_goals`, `training_condition`, 목표 CAS 저장 RPC를 추가한다.
기존 단일 목표는 읽을 때 한 대회로 호환하며 기존 이름·UUID·목표를 임의로 덮어쓰지 않는다.
새 UI는 revision이 바뀌면 409를 반환해 다른 창의 수정을 덮어쓰지 않는다.

`20261016070000`은 recovery 종류와 수행 기록 fingerprint를 추가한다.
계획만 저장했다고 자신의 입력이 바뀌지 않으며, 실제 연결/수동 완료가 변경되면 무효화된다.
`20261016080000`은 설정 시간대를 저장하고 피로 입력이 3일을 지나면 fingerprint를 변경한다.
저장 중 입력 변경은 기존 예약/CAS 검사로 거부하고 기존 계획을 보존한다.

관련 RPC는 service role만 실행한다. `/api/training/prescription`은 관리자 세션과
`current|next` 쿼리만 허용하고 개인 결과를 캐시하지 않는다.
규칙 조회는 AI 생성 한도나 크레딧을 사용하지 않는다.

## 검증

```sh
node --test tests/*.test.mjs
npm run test:prescription:integration
npm run test:db:races
npm run test:admin:integration
npm run lint
npx tsc --noEmit
npm run build
collector/.venv/bin/python -m unittest discover -s collector/tests -v
```

DB 통합 테스트는 별도 임시 계정으로 두 대회·CAS 충돌·처방 조회·고정 응답 계획 생성·재사용·
회복런 저장·수행 변경·생성 중 조건 변경 저장 거부를 확인하고 finally에서 fixture를 제거한다.
SQL 테스트는 트랜잭션을 롤백한다. 실제 관리자 목표나 계획으로 테스트 값을 저장하지 않는다.
