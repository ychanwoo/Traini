# 실제 기록 기반 훈련 진행 화면

`/roadmap`, `/running-analysis`, 마이 요약은 관리자 전용
`GET /api/training/progress`를 사용한다. 조회는 OpenAI를 호출하지 않으며 계획 생성,
활동 가져오기, 완료 연결 수정도 실행하지 않는다. DB 스키마 변경은 없다.

## 표시 범위

- 설정한 `TRAINI_TIMEZONE` 기준 완료된 월–일 8주와 이번 주를 분리한다.
- 로드맵은 여러 대회의 날짜·거리·목표 기록·목표 평균 페이스를 표시한다.
  대회 선택에 따라 D-day와 대회 전·후 보호 구간이 바뀐다. 범위는 기존 `raceCalendar`
  처방 규칙과 같으며, 실제 준비도·기초/역치 훈련 완료를 추정하지 않는다.
- 마이 화면의 예시 VDOT·89% 완료율·평균 거리·Garmin 연결 배지를 제거하고 동일한 실제 요약을 표시한다.
- 목표 기록은 예상 기록이나 현재 수행 능력이 아니다. 달성 확률, VDOT, 회복 점수,
  수면·HRV·의학적 회복 완료를 계산하지 않는다.

## 계산 계약

모든 내부 거리는 m, 시간은 타이머 초, 페이스는 초/km다.
확인된 `garmin_fit`, 정규화 스키마 1, 원본/정규화 해시가 있는 활동만 집계한다.
완료된 주는 기존의 검증된 주간 snapshot을 재사용한다. 일부 측정값이 없으면 확인된
부분 합계와 누락 상태를 표시한다. 정상화되지 않은 스키마는 수행 근거로 사용하지 않는다.

- **주간 평균 거리**: 기록이 하나 이상 있고 모든 활동의 거리가 확인된 주의 거리 합 ÷ 해당 주 수.
  기록이 없는 주와 거리 일부 누락 주를 0으로 넣지 않는다. UI에 사용한 주 수를 표시한다.
- **평균 페이스**: 같은 활동에서 양수 거리·타이머 시간이 함께 있는 활동만 골라
  `총 타이머 초 / 총 거리 m × 1000`으로 계산한다. 저장된 페이스를 단순 평균하지 않는다.
  인터벌·롱런 등이 섞인 평균이며 이지런 처방 속도나 체력 변화가 아니다.
- **최장 거리**: 확인된 개별 러닝 거리의 최댓값. 같은 날 여러 활동을 한 러닝으로 합치지 않는다.
- **증감률**: 직전 두 완료 주에 모두 활동이 있고 거리 누락이 없으며 이전 거리가 양수일 때만 계산한다.
  기록 구성 차이이며 향상·피로·적정 부하 판정으로 사용하지 않는다.
- **이번 주**: 조회 시각보다 미래인 활동은 제외한다. 계획 거리는 저장된 주간 계획 전체,
  실제 거리는 수집된 러닝 합계다. 계획이 없으면 계획 거리를 0으로 꾸미지 않는다.
- **수행 구분**: Garmin 연결 확인, 직접 수동 완료, 미확인, 연결 조회 불가를 분리한다.
  예정된 미래 세션은 오늘까지의 미확인 개수에 넣지 않는다. 수동 완료는 실측 거리가 아니다.
  완료된 주는 직접 건너뜀과 미연결 러닝도 별도로 표시한다. 목표 달성률은 계산하지 않는다.

주간 snapshot의 검증 실패/한도 초과는 오류로 처리하며 부분 조회를 전체 결과로 보이지 않는다.
없는 기록이 실제 휴식인지, 미수집인지 판정하지 않는다.

## 조회 안정성·접근 제어

서버 검증된 관리자 UUID로만 조회한다. 클라이언트가 owner나 조회 기간을 주입할 수 없으며
지원하지 않는 쿼리는 400, 입력 변경 충돌은 409, 조회 실패는 일반화된 503이다.
응답은 `private, no-store`, `Vary: Cookie, Authorization`를 사용한다.

입력 revision을 조회 전후 비교하고 변경되면 최대 두 번 읽는다.
기존 계획을 읽을 때는 `reconcile:false`로 연결 snapshot만 투영한다. 저장된 시간대와 다른
계획을 혼합하지 않으며 완료 연결 조회 실패는 실제 기록 없음으로 숨기지 않는다.
UI는 이전 요청을 취소하고 목표 저장·가져오기 완료·계획 변경·창 복귀·수동 새로고침 후 재조회한다.
조회 실패 시 이전 숫자를 최신값으로 남기지 않는다.

## 검증 명령

```sh
npm run test:progress
npm run test:progress:integration
node --test tests/*.test.mjs
npm run test:admin:integration
npm run lint
npx tsc --noEmit
npm run build
```

실제 DB 통합 테스트는 임시 계정으로 8주 활동·이번 주 활동·두 목표·계획·수동 완료·Garmin
연결을 구성해 집계와 조회 불변성을 확인하고 finally에서 fixture를 삭제한다.
실제 관리자 목표/활동/계획을 수정하지 않으며 실제 모델 호출과 생성 요청은 0회다.
모바일은 320·375·430px과 넓은 화면에서 프레임 폭·가로 넘침·하단 링크 접근성을 확인한다.
