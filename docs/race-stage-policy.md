# 대회 준비·테이퍼·대회·회복 정책 (v2)

로드맵과 계획 검증은 같은 `raceCalendar` 규칙을 사용한다. 날짜는 설정한 훈련 시간대의
달력 날짜로 계산한다. 본 규칙은 애플리케이션의 검증 상한이며, 회복 진단이나 개인별 최적
훈련법이 임상적으로 검증됐다는 뜻이 아니다. 실제 모델 호출 없이 구현·검증한다.

## 단계와 계산 근거

1. **대회 준비**: 테이퍼 전. 임의의 기초·역치 단계나 완료율을 만들지 않는다.
2. **테이퍼**: 총 훈련 거리·품질 훈련 거리를 줄인다. 모든 날을 이지런으로 강제하지 않는다.
3. **대회**: 등록된 대회 거리와 평일 훈련 예산을 분리한다. 대회일 추가 러닝 처방은 거부한다.
4. **회복·복귀 확인**: 기준 기간 이후에도 자동으로 회복 완료를 선언하지 않는다.

기본 테이퍼 일수는 주목표/준비 대회 순서로 5K 7/3일, 10K 7/5일, 하프 10/7일,
풀 14/10일이다. 전체 거리 근거가 확인된 최근 4주를 읽고, 최소 3주 근거에서 마지막 주의
기록 거리가 이전 주들의 중앙값보다 15% 넘게 높으면 기간을 늘린다. 풀은 기록된 중앙값이
65km 이상인 경우에도 기간을 늘린다. 입력일 포함 3일 이내 피로 보고도 반영한다.
상한은 21일이며 기록 부족을 피로로 해석하지 않는다. 15%, 65km 등은 설명 가능한 앱 규칙이며
보편적인 부상 위험 경계값이라고 주장하지 않는다.

초기 회복 확인 기간은 풀 14일, 하프 7일, 10K 3일, 5K 2일이다.
최근 기록 증가와 피로 보고는 기간을 연장한다. 이는 **재확인 시점**이지 정상 훈련 자동 복귀일이 아니다.
거리·중요도는 특히 테이퍼 조정에 사용하며, 준비 대회라는 이유로 풀마라톤의 회복 확인 기간을
단거리 수준으로 줄이지 않는다.

## 테이퍼의 거리·강도 분리

- 대회 전 마지막 이틀은 이지/회복 또는 휴식으로 제한한다.
- 나머지 테이퍼 날짜는 익숙한 짧은 품질 훈련을 허용한다. 일반 주의 고강도 횟수에서
  대회 한 슬롯을 차감하고 추가 세션은 최대 1회다. 허용은 의무가 아니다.
- 작업 구간 거리와 반복 수를 줄이고, 관측된 반복 페이스보다 더 빠르게 처방하지 않는다.
  강훈련 워밍업·쿨다운, 거리 합계, 회복 구간, 훈련일·간격 검증은 유지한다.
- 장거리 날짜와 이지 전용 날짜는 별도로 관리한다. 테이퍼에 롱런을 이지런으로 이름만 바꿔
  넣지 못하도록 날짜별 거리 상한도 적용한다.
- 대회 주간 훈련 거리 상한과 등록된 대회 거리를 분리해, 풀 42.195km가 있다는 이유만으로
  평일 훈련 예산이 음수가 되거나 대회 거리를 중복 차감하지 않게 한다.
- 주간 리뷰가 증가를 권해도 테이퍼 최소 거리를 강제로 올리지 않는다.

## 회복 확인과 단계적 복귀

기준일이 지났어도 고강도·장거리는 자동 허용하지 않는다. 회복 확인 중에는 최소 거리를 0으로 두고
전일 휴식 계획도 허용해, 종전 주간 거리를 채우려고 러닝을 강제로 배치하지 않는다. 복귀 제한을 일부 풀려면
기준일 이후 **최근 3일 내 보통/좋음 입력**과 최근 14일에 확인된 서로 다른 복귀 러닝 날짜
2개 이상이 필요하다. 거리와 타이머가 양수여야 하고, 비교할 과거 페이스가 있으며
짧고 과거 일반 페이스보다 빠르지 않은 기록을 사용한다. 이 조건도 생리학적 회복 완료의 증거는 아니다.

조건을 충족하면 제한된 품질 훈련 최대 1회와 감소된 거리 상한으로 단계적으로 복귀한다.
단계적 복귀 중에는 훈련 날짜에도 보고가 최근 3일 범위여야 하며, 오늘의 정상 보고로 다음 주 상태를 예측하지 않는다.
추가로 대회 전 기록량과 비교 가능한 복귀 주간 기록이 2주 이상 있으면 `return_recorded`로
표시한다. 상태 이름은 `recovered`가 아니며 로드맵 단계도 회복·복귀 확인으로 유지한다.
현재 통증·몸 상태 이상 보고는 다른 조건보다 우선하며 새 러닝을 배치하지 않는다.

대회일 충분한 거리·시간이 없으면 참가·완주를 확정하지 않는다. 8주보다 오래된 대회는
현재 회복 상태를 판정하지 않고 최근 기록 기준을 사용한다. 과거 대회를 영구적으로 이지런 제한의
근거로 쓰지 않으며, 이것도 회복 완료 판정은 아니다.

마지막 목표 대회가 지나도 최근 8주 안에서는 회복 계획을 생성·저장할 수 있다.
`20261017000000_race_stage_policy.sql`과 `20261017010000_legacy_goal_recovery.sql`은
버전·날짜에 따른 입력 검증과 기존 단일 목표의 회복 계획 호환성을 반영한다.
과거·완료 훈련 보존과 예약/CAS 검사를 유지한다. 정책 버전과 설정 시간대 날짜가 바뀌면
저장된 계획에 재검토 표시를 하되 자동 AI 호출·자동 재생성은 하지 않는다.

## 참고 근거와 한계

- [2023 테이퍼 체계적 문헌고찰·메타분석](https://pubmed.ncbi.nlm.nih.gov/37163550/):
  훈련량 감소와 강도 유지의 구분, 21일 이내 테이퍼 연구를 참고했다.
- [B.A.A. 훈련 안내](https://www.baa.org/races/boston-marathon/info-for-athletes/boston-marathon-training/):
  2주 테이퍼 사례가 있다. 해당 계획의 훈련 세션을 복제하지 않았다.
- [HSS 마라톤 후 회복 안내](https://news.hss.edu/how-long-do-you-need-to-recover-after-a-marathon/):
  날짜 하나로 모든 러너의 회복을 확정할 수 없다는 점을 반영했다.

연구 결과를 개인에게 그대로 대입하지 않는다. 사용한 세부 기간·상한·복귀 체크 조건은
설명 가능한 서비스 규칙이며, 사용자 피드백과 실제 수행 근거를 더하는 후속 개선이 필요하다.

## 검증

`node --test tests/race-stage-policy.test.mjs`와 전체 Node 테스트,
`npm run test:prescription:integration`으로 실제 DB의 마지막 대회 후 계획 저장까지 검사한다.
모델 응답은 고정 fixture이며 OpenAI 호출은 없다. DB 테스트는 별도 임시 계정만 사용한다.
