# Workout feedback and explicit skips

오늘·일정의 러닝 세션에서 **훈련 결과·피드백 기록**을 열어 저장한다. 일정 화살표로 지난주·이번 주·다음 주를 볼 수 있다. 지난주는 저장된 계획만 조회하며 계획 생성은 제공하지 않는다. 오늘까지의 훈련만 결과를 기록할 수 있고, 휴식과 미래 세션은 입력 대상이 아니다.

## 입력과 표시

- 완료: Garmin 연결을 유지하거나 직접 완료로 표시한다. RPE는 정수 1–10, 피로는 낮음/보통/높음, 통증은 없음/불편감/통증이다. 각 항목은 선택 사항이며 `null`은 미입력이다. 메모는 200자 이내다.
- 직접 건너뜀: 120자 이내 사유를 필수로 입력한다. 하지 않은 훈련에는 RPE를 기록하지 않는다. 피로·통증·메모는 선택할 수 있다. 일정에는 `× 직접 건너뜀`과 사유를 표시한다.
- 미확인: 직접 완료·건너뜀을 해제하고 해당 세션 피드백도 지우는 명시적 정정이다. 날짜 경과나 Garmin 활동 부재로 미수행을 추정하지 않는다.
- Garmin 기록이 연결됐다면 피드백은 저장할 수 있지만, 완료를 취소하거나 건너뛰려면 먼저 연결을 해제해야 한다. 원본 러닝 기록은 삭제하지 않는다.
- 서버가 보고 시각을 저장한다. 컨디션 기준일은 훈련 날짜다. 오래된 훈련을 오늘 입력해도 오늘 정상/피로 보고로 간주하지 않는다. 현재 상태는 목표 설정의 컨디션에서 따로 갱신한다.

## 저장과 동시성

`POST /api/training/feedback`는 관리자 인증·동일 출처·2KiB JSON 제한·정확한 필드/범위를 검사한다. 사용자 ID는 세션에서만 얻는다. RPC는 소유권·날짜·휴식/러닝 구분·Garmin 연결 상태를 재검사한다.

`workouts`에 assessment, skip_reason, feedback_version, feedback_reported_at을 저장한다. 기존 완료·매칭과 같은 사용자 advisory lock을 사용하고 매칭 스냅샷 revision과 feedback version을 비교한다. 다른 탭의 변경은 409로 반환하며 조용히 덮어쓰지 않는다. 요청 UUID와 payload hash를 이벤트 테이블에 보관해 동일 요청 재시도는 한 번만 적용한다. 변경된 payload에 같은 UUID를 재사용하면 거부한다.

`workout_feedback_events`는 이전 값과 저장 결과를 남긴다. RLS로 관리자 본인만 읽고 브라우저 직접 쓰기는 금지한다. 이벤트는 소유 계정·훈련 삭제 시 cascade 삭제되며, 무기한 독립 보관 자료가 아니다. 일반적인 계획 재생성은 완료·건너뜀·피드백 입력 세션을 보존한다.

## 리뷰와 다음 계획

- 매칭 스냅샷에 피드백을 포함해 주간 리뷰 입력 및 신선도 검증에 연결한다. 화면에서 사유와 입력을 다시 확인할 수 있다. 저장된 이전 리뷰는 자동 재생성하지 않는다.
- 계획 입력에 최근 56일의 보고와 가장 최근 명시적 통증 응답을 포함한다. 보고가 너무 많으면 부분적으로 잘라 정상으로 해석하지 않고 읽기를 실패시킨다.
- 통증·불편감은 기존 `pain` 보호 규칙에 연결해 러닝 처방을 제한한다. 날짜가 지났다는 이유로 이 보고를 해제하지 않는다. 이후 명시적 통증 없음 보고나 더 나중 날짜의 컨디션 정정이 필요하다. `없음` 자체가 의학적 회복 판정이 되는 것은 아니다.
- RPE 9–10 또는 높은 피로는 해당 훈련 날짜의 `tired` 입력으로만 처리하고 기존 3일 신선도 규칙을 적용한다. 새로운 생리학적 지표나 진단으로 변환하지 않는다. 명시적 기존 pain/unwell 보고가 우선한다.
- 주간 리뷰에서 통증·불편감·높은 피로/RPE가 있으면 자동 증가 추천은 허용하지 않는다. 미입력·직접 건너뜀만으로 피로나 부상을 추정하지 않는다.
- 현재 날짜의 직접 건너뜀은 같은 날짜 재처방을 차단하고 남은 거리 상한에서 제외한다. 목표 최저 거리를 채우려고 다른 날에 몰지 않는다. 다음 주에는 미수행 거리를 더하지 않고 실제 기록·부하·대회 단계·컨디션의 기존 상한을 적용한다.
- 저장·정정·조회는 OpenAI를 호출하지 않는다. 실제 AI 계획 반영은 다음 명시적 생성 시에만 이뤄진다.
